** 3D web viewer (the fun one)
There's also a 3D map viewer with flyaround controls in web/:

    ./run-viewer.sh          # serves the repo root on :8000
    # then open http://localhost:8000/web/

It parses the Entities.ini files directly in the browser (web/parser.js is a
port of parser.lua; three.js is vendored in web/vendor/, so it works offline).
Controls: left-drag to rotate, right-drag to pan, wheel to zoom (toward the
cursor), click to inspect an entity, double-click to fly to it, and a
"Jump to Danny" button that flies to the starting character.
The panel lets you toggle points/links/paths/grid/mesh geometry/solid faces/
back-face culling/additive blend and filter individual entity types. Entity
boxes render as edge outlines so nothing hides the level; an invisible pick
proxy keeps them clickable — but hidden types are not clickable. Name labels
show only for ADanny and APropTriggerEndLevel, unconditionally.
AMusicTrigger and AWorldSectionVolume start hidden (legend unchecked).
Game coordinates are +y down and mirrored along z, so the viewer renders
(x, -y, -z) to match the in-game layout.
Entity AABB boxes follow the engine's convention (verified in the combined
vmtext ELF, FUN_7f0847a8/FUN_7f084640): AABBDimensions are HALF-extents and
Position.y is the TOP of the volume, so the drawn box spans (x±w, y−2h..y,
z±d) in game coordinates — 2× the raw dimensions, hanging below Position.y.
This is what makes ADeathZone boxes line up with the actual in-game kill
areas (the kill test is AABB-vs-AABB with the player's collision body).
Deep-link to a level with a hash: /web/#SpongeBobLevel2

** Collision / mesh geometry
Level geometry is extracted from the GameCube disc (TRB container, Toshi
engine) into web/collision/<level>.json and rendered as SOLID meshes. Each
mesh is a GX-style INDEXED triangle strip: the mesh record's 0x98 index
block walks (posIdx, nrmIdx, texIdx) per strip vertex and the repeated-index
(degenerate) triangles are the engine's strip-restart markers, so the
faces are the strip's real triangles (the old "vertex run is the strip"
reading drew faces from the wrong indices — fixed this session). The solid faces render as one uniform shell instead of the rainbow-per-mesh
look: all faces share a single style that's Gouraud shaded by the scene
lights (smooth per-vertex normals via computeVertexNormals, so angle-based
lighting makes floors/roofs/walls read by orientation) and tinted by height
— a subtle cool->warm ramp (blue low, amber high) spread across the level's
y-range. Shading and tint are always on; the only knob is "Translucent faces
(additive blend)" (off by default): additive blending at 50% opacity with
depthWrite off — addition is order-independent, so the classic
semitransparent z-sorting artifacts (distant faces popping through nearer
ones) become brighter glows on overlap instead. Controls: "Mesh geometry"
shows/hides the group, "Mesh faces (solid)" the surfaces (default on).
"Cull back faces (see through roofs/walls)" is on
by default: the solid meshes render with THREE.FrontSide, so surfaces whose
front faces point away from the camera (ceiling bottoms from above, outer
wall faces, floor undersides) are culled and entities inside buildings show
through. The engine's winding convention is "front = the side the player
sees" (floors up, ceilings down), so floors stay visible from above;
uncheck it for the full double-sided look.

Re-extract with:

    cd asset-extract && python3 tools/trb_mesh.py --web

(set NICKMAPPER_WEB=$PWD/web/collision if the repo is reached through a
symlink and the automatic repo-root walk can't find web/index.html). The
--web export writes the mesh-v2 format: per-mesh raw (x, z, y) s16
fixed-point vertex runs at 1/64 scale (data.div, yDown — the raw y is +y
down, game-native; entities are +y up), record centers/radii, format flags
and the indexed face strips ("faces": the strip's posIdx stream, when the
mesh's index block decodes); the OBJ files (output/mesh/) stay available
for offline viewing. Meshes whose index block is a junk record or whose
indices exceed the own chunk (a true shared pool living in another
section) get NO faces — the viewer draws their pool as lines only rather
than guess (the old 3/4/5-byte search also mislabeled the recw-6/7 flags
0x06020201/0x06020101 as a "shared-pool" variant; they decode fine once
the search includes recw 6/7).

The per-mesh collision blocks that follow each vertex pool are exported as
raw bytes only (each mesh's "coll" array, "collFormat": "unknown") — the
byte extractor is kept, but nothing interprets the bytes. The collision
mesh format is UNKNOWN: every 8-bit coordinate reading tried so far (4-byte
(flag,x,y,z) s8 records with a (s8+128)/255 bbox dequant, the later 3-byte
u8-triple "walkmesh", 5-byte walls) was an unverified structural hypothesis
and is unlikely to be correct (see docs/collision-status.md). The footprint
overlay and footprints JSONs were removed (blank slate) until the DOL's
collision reader is located (Dolphin trace).

Source: the gcn+wii/extract project's nicku-ntsc/P-GNOE/files/Data/<level>/
(*.trb level parts — selection is name-agnostic: any file whose SYMB table
lists W0C0M meshes, so the DP naming quirks DPWorld_Level01_01.trb /
DPWorld_Detail_level02_01.trb work). The old 5-byte "wall column" reading
was wrong: those arrays were NameHash coincidences. The real geometry is
mesh-based — 86+ per-part meshes, each a 52-byte record (center + radius,
offsets, count, format flag) plus a C-block whose contents are not yet
decoded — an earlier u8-triple "walkmesh" reading is probably wrong, and
the collision mesh format is unknown.

Verified: scale 1/64 confirmed for all level parts (mesh-record centers
match vertex-run midpoints); with the y sign corrected (file y is +y down)
the entity overlay jumps from 9% to 37% of in-bbox entities and every part
improves — entities stand on the geometry (part 01's original 82% check was
sign-blind: its floors sit at y=0). The container, RELC pointer map and
52-byte records are fully decoded (see asset-extract/docs/trb-format-notes.md).

Topology status: SOLVED (this session) — the mesh is an INDEXED triangle
strip, not a bare vertex run: the 52-byte record's u32[+0x20]/u32[+0x24]
point at a [0x98][u16 count][count x triples] block where each record is
(posIdx, nrmIdx, texIdx) with the pos index first. The layout rules are
now analytic, not heuristic:
  * pos is the FIRST field (misaligned reads that tile a pool are false
    positives — the nrm stream can coincidentally look like a strip).
  * pos index width is DERIVED from the pool: u8 iff pool <= 256, u16
    iff pool > 256 (GX_INDEX8/16) — verified 100%% (zero violations)
    across 9,264 mesh records / 69 parts / 8 flags.
  * the record width IS stored in the format flag: 0x06020202 -> recw 3,
    0x06020203 -> recw 4, 0x06030202 -> recw 4, 0x06030203 -> recw 5,
    0x06020201 -> recw 6, 0x06020101 -> recw 7, 0x06030101 -> recw 8.
So "how does the game know": the flag tells it the per-mesh attribute
layout, and the pool size tells it the index width at load (the
GXSetVtxDesc call). No width tables exist in the file or in loose files.
The extractor tries recw 3..12 pos-first and keeps the strip that tiles
the pool cleanly; a decode is accepted only if the pool sits in the
record's bounding sphere and the strip is manifold (no edges shared by
>2 triangles, no edge over 2.2x the record radius, >60% pool coverage).
Consecutive posIdx walk the strip; the repeated-index (degenerate)
triangles are the strip-restart markers; the pool is the vertex chunk's
first max(posIdx)+1 triples. No fixed coordinate cap applies to pools
(levels span the full s16 range; a hardcoded 12000 wrongly rejected
JN's bigger meshes this session — fixed).

Verified on SB part 01: 85/86 meshes decode to perfect manifolds (zero
edges shared by >2 triangles, 100% pool coverage), the floor tiles
triangulate exactly (2.24-unit tiles -> 10419 raw^2 per triangle pair),
and the road-line mesh becomes 8 clean dash quads (16 triangles) instead
of the old 22-triangle decode with 10 garbage spanning slivers. Level-wide
(9 levels, 8,467 meshes): 6,652 meshes carry faces (78.6%%, up from
61.7%% after the recw 6/7/8 + pos-first + scale fix), 430k+ triangles,
and only ~72 (0.007%%) exceed 2.2x their mesh radius — the rest of the
"stretched" look was the lines-only fallback plus legit long triangles in
coarse meshes (e.g. SB3 k=16, a 9.85-unit wall panel within its 5.98-radius
record). The smooth-mesh flags 0x06030202/03 have lower pool coverage
(avg 0.79) but zero oversized edges — restart-heavy strips sharing a
pool, not garbage. The earlier "split at jumps > 270" heuristic and the
"vertex run is the strip" reading were wrong; the old decode drew faces
from the wrong indices. The giant-triangle bug (1-2 per map) is fixed:
the pool section comes from the +0x10 RELC relocation target, not from
k+1 — level-global mesh tables (DPWorld_Level04_01_Detail, JN parts
03/05) shift the mesh->chunk mapping, and reading k+1 grabbed the wrong
chunk as the pool. With the fix: 8,916/9,127 meshes carry faces (97.7%%),
no triangle exceeds ~2x its record radius. Still open: meshes whose
+0x10 relocates to section 0 (their pools live in the SECT — a true
shared pool, still undecoded), the collision mesh format (the C-block's
u8-triple "walkmesh" reading is probably wrong), and the texture
pipeline —
the .ttl files hold the textures (TGA-named entries, raw pixel data) and
chunks hold UV arrays, but the UV count mapping and the texture format
are unsolved (see asset-extract/docs/trb-format-notes.md §10). The main.dol was set up
in Ghidra (GX library located at 0x80006xxx..0x8003Exxx) but its
mesh-parsing code is reachable only through function-pointer tables and
was not pinned statically — see asset-extract/docs/trb-format-notes.md §7
for the next steps (dolphin trace / vtable walk).

Notes vs the Lua pipeline:
  * parser.js also captures Orientation quaternions so boxes rotate in 3D.
  * It ignores quoted `Type = "...";` properties (parser.lua has a latent
    bug there that clobbers the entity's real type, e.g. APropShakable).
  * Levels are loaded from ../levels/ relative to the page, so serve the
    repo root (see run-viewer.sh) — don't open web/index.html via file://.

Tests: web/test-headless.sh (dump-dom smoke test), web/test-e2e.mjs
(headless chromium + CDP: loads a level, clicks an entity, switches levels)
and web/test-meshv2.mjs (Node-only: validates the mesh-v2 decode of every
level JSON without a browser).

* Reverse-engineering scripts

The scratch tooling that cracked the TRB/DOL formats lives in scripts/ (it was
previously scattered in /tmp):

  scripts/trb/      # TRB container scanners (scan_pool.py, w2_scan.py)
  scripts/dol/      # main.dol analysis (dol2elf, doldis, w4_scan, ghidra_dol)
  scripts/dol/probes/ # one-shot w4b..w4v probes (investigation log)
  scripts/util/     # misc helpers (diffcmp.sh image diffing)

They default to the mounted disc-extract root; override with
NICK_EXTRACT=/path/to/extract. See scripts/README.md.

**RE quickstart (what everyone forgets):**

- ISO: `nicktoonsunite.iso` (P-GNOE, GCN) on the removable drive at
  `games/console (other)/gcn+wii/` (mount: /run/media/<user>/<uuid>/... — the
  user name varies; find it with `findmnt` or NICK_EXTRACT).
- Binary: decompile `vmtext_combined.elf` — the DOL + the engine image
  vmtext.bin (0x7f004000) merged; rebuild it any time with
  `scripts/dol/build_combined_elf.py` (byte-identical output, so the cached
  Ghidra project stays valid). The collision system, TTRB loader and mesh
  records are all in vmtext; the DOL's OpCODE is dead code.
- Collision notes: `asset-extract/docs/collision-runtime.md` (live session
  findings) + `docs/collision-status.md` + `asset-extract/docs/trb-format-notes.md`.
